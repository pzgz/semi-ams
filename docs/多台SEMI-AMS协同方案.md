## 1. 目标

几台 SEMI-AMS 各装一种耗材，出料口经过一个多进一出的合流件（Y 型或多通），汇成一路接到打印机唯一的外置料盘入口。打印时如果用外置料盘，**由对应耗材的那一台自动送料**，其它几台不动；打完退料也只由这一台退。

以后可以再扩展的（不在第一步里）：

- 两台装同样的耗材，一台用完另一台接着送（续料）。
- 多色任务全部映射到外置料盘时，按换色自动切换进料器（取决于 P2S 是否支持，见 4.3 节）。

## 2. 前提和限制

- **打印机不知道有几台进料器。** P2S 只有一个外置料盘（`vir_slot` 255），消息里只说"这次用外置料盘"和"外置料盘设成了什么耗材"。选哪一台只能由进料器自己判断。
- **每台各自连打印机的 MQTT、各自判断。** 几台听到的是同一份消息，只要规则一样，就能得出同一个结论，彼此不用通信。实测 2 个客户端同时连接没问题，打印机最多允许几个客户端还要测。
- **只读。** 目前固件只发 `pushall`，不向打印机发控制命令。凡是要写打印机的做法（例如自动修改外置料盘的耗材设置），都要另外决定。
- **ESP8266 内存小。** 连上点灯和打印机后空闲约 13KB，下载和解压 3MF（至少要 32KB 的解压窗口）在进料器上做不到。
- **机械上**：没被选中的几台，料头必须退到合流件之前，否则会挡住被选中那一台的耗材。被选中那一台从自己的就绪开关送到打印机，路径比现在长一段合流件，首次送料超时（`first_feed_timeout_s`，默认 120 秒）可能要加大。

## 3. 能用的信号

| 信号 | 来源 | 用途 |
|---|---|---|
| `vir_slot[0].tray_type`、`tray_color`、`tray_info_idx` | 每条 `push_status` | 外置料盘现在设成了什么耗材 → 选哪一台 |
| `project_file.ams_mapping2` | 开始打印 | 这次是否用外置料盘（现有逻辑） |
| `project_file.url` | 开始打印（云打印） | 打印文件下载链接，3MF 里有这块板要用的耗材 |
| `mapping` | 每条 `push_status` | 当前任务是否用外置料盘（中途接入时用） |
| `print_error` `0x07FFC006` | 进料阶段 | 打印机在等外置料盘的耗材 |
| `print_error` `0x07FFC003`、`ams_change_filament` | 退料 | 现有逻辑 |
| `device.extruder.info[].snow` / bit1 | 每条 `push_status` | 当前料盘、挤出机里有没有耗材 |

## 4. 三种做法

### 4.1 做法一：按外置料盘的设置匹配（推荐第一步）

**思路**：每台记住自己装的是什么耗材；打印前用户在打印机屏幕、App 或 Studio 里把外置料盘设成想用的那卷（拓竹本来就要求设对，喷嘴温度才对）；开始打印时，耗材和 `vir_slot` 对得上的那一台送料。

**每台的设置**（网页和点灯 App）：

- 我的耗材：类型（如 `PETG`）、颜色（如 `057748`），可选的耗材预设编号（如 `GFG99`）。
- 按钮"读取打印机当前的外置料盘"：一键把 `vir_slot` 的类型、颜色、预设记成"我的耗材"。日常用法：把外置料盘设成这台的耗材 → 在这台上点一下。
- 优先级（同样的耗材装了两台时用，第一步可以先不支持，在网页上提示"有重复"）。

**判断规则**：

- 类型相同（不分大小写）且颜色相同（只比 RGB，不比透明度）；设置了预设编号的还要预设相同。
- 收到"开始打印"且用外置料盘时：对得上的那一台照现在的逻辑送料；对不上的写一条日志"外置料盘是 PLA 白，本机是 PETG 绿，不送料"，然后什么都不做。
- 退料：现在的状态机只在"打印中"响应打印机的退料，没选中的几台本来就不在"打印中"，不用改。但"打印机空闲时耗材离开了打印机"这条备用判断要限制为只对本次送料的那一台生效。
- 一台都对不上时：每台都不送料，网页和 App 提示"外置料盘的耗材没有对应的进料器"。
- 没有设置"我的耗材"的进料器按现在的方式工作（单台使用不受影响）。

**界面**：网页"拓竹打印机"卡片和点灯 App 显示"外置料盘：PETG 深绿 / 本机：PETG 深绿 ✓"。

**改动范围**：`settings`（新增三个设置项）、`bambu`（解析 `vir_slot`，状态里加"外置料盘耗材"）、`printer`（开始打印时做匹配，不匹配就不调用 `requestPrinterStart`）、网页、点灯控件、仿真测试。

**动手前先测**：

1. 开着 `bambu_listen.py`，在打印机屏幕上改一下外置料盘的耗材，看 `vir_slot` 是不是马上更新；再分别在 App 和 Studio 里改一次。
2. 在 Studio 发送打印、选择外置料盘时，看它会不会顺便改掉外置料盘的耗材设置。
3. 同时开 4–5 个监听程序，看打印机最多接受几个 MQTT 客户端。

### 4.2 做法二：协调程序读打印文件（全自动，需要一台常开的设备）

**思路**：在 NAS、Docker 或一直开着的电脑上跑一个小程序（可以从 `tools/bambu_listen.py` 改），监听打印机的 MQTT：

1. 收到 `project_file` 后，用 `url` 下载 3MF（云打印是 1 小时内有效的 HTTPS 链接），读 `Metadata/slice_info.config`，得到这块板要用的耗材（类型、颜色、预设编号、用量）。
2. 按 `ams_mapping2` 找出映射到外置料盘的那一种。
3. 通过进料器的网页接口（新增，例如 `POST /api/select`）告诉对应的那一台"这次是你"，其它几台"这次不是你"。

**好处**：不需要用户打印前去改外置料盘设置；还能在开始前检查"需要的耗材有没有装"，没装就提醒。

**问题**：

- 多一个要一直运行的程序，它不在线时要退回做法一。
- 从 Studio 局域网直接发的任务，`url` 是打印机本地路径，要用 FTPS 从打印机下载，云模式下的 P2S 能不能这样取还没测。
- 如果还想顺便把打印机的外置料盘设置改对（`ams_filament_setting` 命令），就是向打印机写命令了，要另外决定。

### 4.3 做法三：外置料盘多色换料（待验证）

**思路**：如果 P2S 允许多色任务的几种耗材都映射到外置料盘，并在每次换色时暂停、提示手动换料，那么换色时的消息（`ams_change_filament`、`extruder.star`、`print_error`）里很可能写着下一种要什么耗材。这样就能做到：A 台退料 → B 台进料，自动多色打印。

**先做的实验**：切一个两色的小模型，两种颜色都映射到外置料盘（看 Studio 是否允许），开着监听程序打印一次，记录换色时的完整消息。

## 5. 顺带要做的改进（单台也有用）

1. **中途接入**：SEMI-AMS 重启或者打印开始后才连上打印机时，会错过 `project_file`。如果连上后看到 `gcode_state` 是 RUNNING / PREPARE、`mapping` 里有外置料盘、挤出机里有耗材，而本机有料，就进入"打印中"继续补料。多台时还要先通过做法一的匹配。
2. **`0x07FFC006`（打印机在等外置料盘的耗材）**：本机该送料却还没在送（例如错过了开始打印），就开始送料；已经在送就不处理。要防止和用户手动操作冲突，例如只在进料阶段（`stg_cur` 4）响应。
3. **点灯 App 显示打印进度**：任务名、进度百分比、剩余时间、当前层。

## 6. 实施顺序

1. 做 4.1 节的三个测试，结果补进 [拓竹MQTT消息参考](拓竹MQTT消息参考.md)。
2. 固件：做法一 + 第 5 节的 1、2 条，补仿真测试，单台先上板验证不受影响。
3. 机械：合流件、各台的退料距离（`unload_extra_ms`）、首次送料超时。
4. 两台上板联调：切换外置料盘设置 → 打印 → 退料，确认只有一台动作。
5. 视需要再做做法二的协调程序、做法三的实验。

## 7. 未决问题

- 打印机允许几个 MQTT 客户端同时连接？
- `vir_slot` 在屏幕、App、Studio 上修改后多久更新？Studio 发送任务时会不会改它？
- 两台装同样耗材时谁送：固定优先级，还是做续料？
- 每台的缓冲器在合流件之前，合流件到打印机这一段没有缓冲。被选中的那台照常按自己的缓冲器补料，按理没有问题，要实际试。
- 没被选中的进料器料头停在哪里才不会挡路，`unload_extra_ms` 要多大。
